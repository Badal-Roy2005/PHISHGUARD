## Parallelism

```
M0 → M1 ─┬─► M2 ──────────────────┐
         ├─► M3 → M4 ─┬─► M5 ─────┤
         │            └─► M6 ─────┤
         ├─► M8 (migrations) ─────┤
         └──────────► M9 shell ───┴─► M7 → M9 finish → M10 → M11 → M12
```

Must stay sequential:

- M0 → M1 (nothing can be built against an unfrozen contract).
- M3 → M4 (guard exists before any fetch).
- M4 → M5/M6 (all egress uses the guard).
- M2 + M3 + M5 + M6 → M7 (scoring needs engines).
- M7 → M9 finish (UI renders a real assessment).
- everything → M11 → M12.

Parallelizable: M2 ∥ M3 after M1; M5 ∥ M6 after M4; M8 migration authoring ∥ M2–M7;
M9 layout shell ∥ backend work.

## Per-milestone template

Each milestone must record: objective, dependencies, files created, files modified,
implementation details, API contracts touched, database changes, required tests,
acceptance criteria, rollback.

Rollback is always `git revert <sha>` or deleting the branch. Destructive git is
forbidden (see `AGENTS.md`).

## M2 outcome (done)

- Audited 235,795 × 56 rows: 0 missing, 0 exact duplicates, 425 duplicate URLs,
  175,509 registrable domains, 120 domains carrying both labels.
- Split by registrable domain (`tldextract`, offline snapshot), class-stratified,
  70/15/15, seed 42. Duplicate URLs and ambiguous domains removed. Result:
  166,343 / 32,556 / 35,099 rows, no domain shared across splits.
- Compared Logistic Regression, Random Forest and XGBoost on two feature sets:
  `full_offline` (46 features, page-content included, research only) and `live`
  (18 URL-only features, served).
- Selected `live` / XGBoost on validation phishing F1. Held-out test: accuracy
  0.9968, phishing precision 0.9993, recall 0.9932, F1 0.9963, ROC-AUC 0.9983,
  PR-AUC 0.9986. All values measured from the run, not targets.
- SHAP `TreeExplainer` for the served model; per-row contributions and global
  importance are produced.
- Implemented `GET /model/info`, `POST /predict`, `POST /explain`, the
  `ok | partial | unknown` missing-feature policy, and explicit 503 without
  artifacts.
- Artifacts, model card, manifest, metrics and checksums are generated by
  `uv run python -m training.train`.

## M3 notes (next)

  model or the model through those checks.
- Every engine reports `status`, `findings`, `evidence`, `source`, `duration`.
- An unavailable check must propagate `unknown`/`error`, never `safe`.
- M4 must exist before any outbound fetch, including redirect destinations.
